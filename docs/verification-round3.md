## 生产浏览器检查

14 / 14 通过：

1. 五章节各取样一次，始终只有一个主 ScrollTrigger 和一个持续复用的 Canvas。
2. 多次非相邻跳转后回到相同进度，相机、爆散量、雕塑量与展开量一致。
3. 在重生章节刷新后恢复滚动位置与相机。
4. 原生章节菜单及带 hash 的刷新落在对应时间轴边界。
5. 手动 CLOSED 从当前可见展开量接管；继续滚动后归还叙事控制。
6. 桌面拖动、直接点击花心及静止长按松开可用。
7. 四种材质在滚动后均可编译，WebGL 无错误；反复跳转后 GPU 资源计数稳定。
8. 桌面结尾 Replay 在视口内，点击后清除旋转、脉冲和爆散并返回开头。
9. 减少动态效果下固定相机，保留叙事与手动控制，滚动立即解除旧展开覆盖。
10. 390 × 844 移动视口可访问五章，无水平溢出，使用 27 片花瓣和一个 Canvas。
11. CDP 单指触控拖动旋转；花朵区域外的触控可滚动页面。
12. 320 / 430 / 390 宽度切换后仍只有一个主时间轴，Replay 可达，结尾正文和页脚不重叠。
13. 主动丢失 WebGL 上下文后显示二维轮廓，保留五章节原生内容。
14. 无 hydration、浏览器运行时或 shader 错误。

桌面反复跨章和切换材质后，已预热的几何体计数保持 25，纹理计数保持 11。该检查证明所测试操作期间未持续增长，不替代长时间运行和真实设备的内存分析。

## 帧耗时与设备范围

在 FRACTURE 高负荷阶段，每个配置预热后采集 120 个 requestAnimationFrame 间隔：

| 视口 | 材质 | 中位数 | P95 |
| --- | --- | --- | --- |
| 1440 × 960 桌面 | 银色 | 6.1 ms | 6.2 ms |
| 1440 × 960 桌面 | 玻璃 | 6.1 ms | 6.3 ms |
| 390 × 844 移动模拟 | 银色 | 6.1 ms | 6.2 ms |
| 390 × 844 移动模拟 | 玻璃 | 6.1 ms | 6.2 ms |

移动模拟使用同一台电脑的 GPU；以上为浏览器帧间隔，不能解释为真实手机的性能保证。玻璃透射、全视口填充和文字纹理仍是主要 GPU 成本，已限制 DPR、移动花瓣数、透射分辨率与环境分辨率。真实低端手机和 Safari 仍建议按时间轴指南手动复查。

## 重跑方法

在项目目录执行：

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npm run start
```

打开服务器输出的本机地址，按 [时间轴指南](cinematic-timeline.md) 的手动验收步骤检查五章、倒放、快速跳转、刷新、触控、减少动态效果及 Replay。开发时使用 `npm run dev`。

自动浏览器执行记录与阶段截图保存在本机被 Git 忽略的 `artifacts/` 目录：`cinematic-verification.json`、`cinematic-frame-timing.json`、`round3-*-desktop.png` 和 `round3-*-mobile.png`。浏览器工具使用当前环境已有的 Playwright 与 Edge，不向项目增加运行依赖。
